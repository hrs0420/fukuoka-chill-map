# 作業メモ

## フェーズ1: データと生成物の品質チェック

- リンク検査は `spots/` に限定せず、リポジトリ内のHTML全体を対象にした。今後生成するカテゴリ一覧・記事・エリアページも特別な設定なしで検査でき、共通ナビなどのリンク切れも検出できるため。
- 相対リンクはHTMLファイルの置かれた階層から解決し、クエリとフラグメントを除いた実ファイルの存在を確認する。外部URL、ページ内アンカー、ルート相対URLは今回指定された「相対パスのリンク先ファイル」検査の対象外とした。
- GitHub ActionsではNode.js 20を使う。Node.js標準機能のみでビルドと検査を実行でき、ビルド後はtracked差分と未追跡ファイルの両方がないことを確認する。

## フェーズ2: カテゴリ一覧ページの静的化

- 静的一覧は同じカードCSSと、一覧画面にある説明・ランニングタグ・お気に入り表示を含めた。JavaScriptが無効でも情報を読め、JavaScript有効時は従来の一覧機能がデータを読み直して表示する。
- 旧 `list.html?category=...` は未知のクエリも含め `location.search` 全体を転送する。検索や絞り込みを含む共有URLのパラメータを欠落させないため。
- 静的ページのcanonicalは検索条件を含まない `spots/{category}/index.html` に固定し、JavaScriptによるURL更新後も同じcanonicalを保つ。

## フェーズ3: まとめ記事の仕組み

- 記事一覧ページは公開記事が0件でも生成し、公開中の記事がない旨を表示する。記事導線を常に有効にし、記事追加時にURLが変わらないため。
- `draft: true` の個別HTMLは生成せず、過去に公開状態から下書きへ戻した際も古いHTMLを残さないよう、ビルド時にその記事の生成ファイルを削除する。sitemapにも下書き記事を含めない。
- 初期の `data/articles.json` は仕様どおり下書きサンプルを1件だけ置き、全テキストにサンプルであることを明記する。
- `updated` が省略された記事は更新日を画面表示せず、Article JSON-LDにも `dateModified` を出さない。公開日を更新日と推測しないため。
